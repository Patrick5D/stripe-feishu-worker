# Stripe Feishu Worker

Cloudflare Worker that verifies Stripe and Waffo webhook events and sends payment notifications to a Feishu custom group bot. It does not change product orders or credit balances.

## Events

Custom payment notices are sent for:

```text
checkout.session.completed
  One-time Checkout only: mode=payment and payment_status=paid.

checkout.session.async_payment_succeeded
  Delayed one-time Checkout payment success.

invoice.payment_succeeded
  Subscription invoices only: billing_reason starts with subscription and amount_paid > 0.
```

Subscription-mode `checkout.session.completed` events are ignored. Their first
payment and renewals are reported by `invoice.payment_succeeded`, preventing two
payment notices for one subscription checkout.

Payment notices use Feishu interactive cards. Successful payments are green,
failures are red, refunds are orange, and subscription changes are blue.

Payment card fields:

```text
💰 {project label} · 新{月费/年费/积分包/订阅}
金额
邮箱, falling back to the Stripe customer id
来源国家, from Checkout/Subscription metadata origin_country
账单国家, with an ISO country flag
注册时间, from low-sensitivity Checkout/Subscription metadata `signup_at`
首次来源, from `first_touch_source` plus optional `first_touch_medium`
来源活动, from optional `first_touch_campaign`
类型
环境, live or test
时间, Asia/Shanghai
Stripe event id
```

Missing email and country values are omitted instead of displaying `unknown`.
Missing registration or acquisition metadata is also omitted, preserving
backward compatibility for existing Checkout Sessions and projects that do not
yet capture attribution.
Checkout email prefers `customer_details.email`; invoice notifications use the
finalized customer snapshot on the invoice.

Other supported notices:

```text
invoice.payment_failed
customer.subscription.created
customer.subscription.updated
customer.subscription.deleted
charge.refunded
```

`customer.subscription.created` still reports the first subscription creation.
The later Stripe cleanup transition from `incomplete` to
`incomplete_expired` is ignored because it represents an unpaid first invoice
expiring, not a new customer action or successful payment.

## Add A New Project

Each project needs three public identifiers and one private Stripe secret:

```text
slug
  URL-safe project id used in the endpoint path.
  Example: erasio

label
  Human-readable name shown in Feishu.
  Example: Erasio

secret env name
  Uppercase Cloudflare secret binding used by the Worker.
  Example: ERASIO_STRIPE_WEBHOOK_SECRET

Stripe endpoint signing secret
  The whsec_xxx generated by Stripe after creating the webhook endpoint.
  Store it with wrangler secret put; never commit it.
```

### 1. Add The Env Binding Type

Edit `src/index.ts`:

```ts
type Env = {
  ERASIO_STRIPE_WEBHOOK_SECRET: string;
  PLAYITOUT_STRIPE_WEBHOOK_SECRET: string;
  MOTIOFY_STRIPE_WEBHOOK_SECRET: string;
  BUILDVISUALS_STRIPE_WEBHOOK_SECRET: string;
  FEISHU_WEBHOOK_URL: string;
  FEISHU_BOT_SECRET: string;
};
```

### 2. Add The Route Mapping

Add an entry in the site route table:

```ts
const sites: Record<string, SiteDefinition> = {
  "/playitout/stripe/webhook": {
    slug: "playitout",
    label: "PlayItOut",
    stripeWebhookSecretName: "PLAYITOUT_STRIPE_WEBHOOK_SECRET",
  },
};
```

### 3. Deploy The Code

```bash
npm run typecheck
npx wrangler deploy
```

### 4. Create The Stripe Endpoint

In the matching Stripe account, create a webhook endpoint:

```text
https://bingo.thecelesteway.com/playitout/stripe/webhook
```

Subscribe at least:

```text
checkout.session.completed
checkout.session.async_payment_succeeded
invoice.payment_succeeded
invoice.payment_failed
customer.subscription.deleted
charge.refunded
```

Copy the generated endpoint signing secret:

```text
whsec_xxx
```

### 5. Store The Stripe Secret

```bash
npx wrangler secret put PLAYITOUT_STRIPE_WEBHOOK_SECRET
```

Paste the `whsec_xxx` value when Wrangler prompts.

### 6. Verify

Health check:

```bash
curl -sS https://bingo.thecelesteway.com/health
```

Expected:

```json
{ "ok": true, "service": "stripe-feishu-worker" }
```

Unsigned webhook requests should fail:

```bash
curl -i -X POST https://bingo.thecelesteway.com/playitout/stripe/webhook
```

Expected:

```text
400 Missing Stripe signature
```

Then verify from Stripe Dashboard webhook attempts. A successful delivery returns HTTP 200 and sends a Feishu message.

```text

secret: {SLUG}_STRIPE_WEBHOOK_SECRET, with hyphens converted to underscores

```

## Security

- Do not commit `whsec_xxx`, Stripe API keys, Feishu webhook URLs, or Feishu signing secrets.
- Store runtime secrets only with `wrangler secret put`.
- The public endpoint is safe to expose because Stripe signatures are verified before notifications are sent.
- Test and live Stripe endpoints have different `whsec_xxx` values. Use separate paths or separate Workers if both must be active.

## Waffo / Build Visuals

The Waffo route accepts only `order.completed` for store
`STO_6UnVcck9q54NexgyLmWssn`. Production sets `WAFFO_ENVIRONMENT=prod`.
It verifies the unchanged raw body using `x-waffo-signature` and the SDK's
platform public key, then checks store and mode. This Worker needs no Waffo
merchant private key or Stripe-style signing secret.

`chargedAmount` is already a display amount (`"9.00"` means $9, not nine cents).
Missing charged amounts are omitted rather than replaced with zero or a list price.
Cards include the Waffo channel, product, order, email, country, registration and
attribution metadata where available. Other Waffo event types return 200 without
sending a card. Test-mode cards have an explicit test title.

The existing product callback remains responsible for credits:
`https://buildvisuals.com/api/payment/notify/waffo`.
Add a second **Raw HTTP / Production** webhook in Waffo:
`https://bingo.thecelesteway.com/buildvisuals/waffo/webhook`, subscribing only to
`order.completed`. Deploy the route before adding this webhook.

Unsigned probes must return `400 Missing Waffo signature`.
A signed supported event returns 200 only after Feishu HTTP and business success.
Feishu failures propagate to a non-2xx response so Waffo can retry.
Delivery is at least once: this sidecar has no persistent deduplication, and a
retry may produce a duplicate card. Event IDs remain visible for identification.

For integration testing, run the same Worker locally with
`WAFFO_ENVIRONMENT=test` and a temporary test-mode HTTP webhook. Use a real Waffo
sandbox checkout; the merchant private key cannot forge platform webhook signatures.
Remove the temporary webhook and tunnel afterward. Never weaken the production
route to accept test events. Existing Stripe routes and secrets remain unchanged.

`nodejs_compat` supplies the Node crypto APIs used by `@waffo/pancake-ts`.
The SDK is pinned to 0.25.0; its default timestamp window is preserved.
